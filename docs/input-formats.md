# Input Formats: Metadata Sheet And FOFN Files

This page is the reference for the two kinds of input files the pipeline reads:

1. the **metadata sheet** (`*_samplesheet.txt`) — required for every input type
2. the **Bactopia input manifest (FOFN)** — one contract per input type

If you only need the command examples, see the main
[README](../README.md). This page focuses on exact file shapes so you can
build them by hand or check what the launcher generated.

## Quick Reference

| Input type | Manifest file | `runtype` | Read/assembly column | Auto-generated by launcher? |
| --- | --- | --- | --- | --- |
| `illumina` | `samplesheet.fofn` | `paired-end` | `r1` + `r2` | yes, from the input directory |
| `ont` | `samplesheet.ont.fofn` | `ont` | `r1` only | yes, from the input directory |
| `assembly` | `samplesheet.assembly.fofn` | `assembly` | `extra` | yes, from the input directory |
| `accession` | *(none — plain text list)* | n/a | n/a | no manifest; you supply the list |

All FOFN files share the same 5-column, **tab-delimited** header:

```text
sample	runtype	r1	r2	extra
```

Empty cells must stay as empty tab-delimited fields — do not drop the columns.

## The Metadata Sheet (required for all input types)

The metadata directory must contain exactly one `*_samplesheet.txt` unless you
set `AGRF_SHEET_PATH` explicitly. This sheet is mandatory for Illumina, ONT,
assembly, SRA/ENA accession, and NCBI assembly accession runs.

### Columns

The sheet needs two columns:

- **column 1** — the sample identifier, used to join metadata back onto results
- **column 2** — the organism/phenotype note used by MLST review logic

How the mapper picks those columns
([`map_samplesheet_results.R`](../scripts/map_samplesheet_results.R)):

- if headers `Sample name` **and** `Comments` are **both** present, they are
  used by name;
- otherwise it falls back to **position** — first column as the sample name,
  second column as the organism/phenotype note. Internally the second column is
  renamed to `Comments`, so a sheet headed `Sample name` + `Organism` works
  correctly as long as the organism is the second column.

### Format rules

- **Delimiter**: tab **or** comma. The validator auto-detects it from the first
  line (a tab anywhere in the header line means tab-delimited, otherwise comma).
- **Header matching** is case-insensitive and whitespace-normalized, so
  `Sample Name`, `sample name`, and `Sample  name` all resolve to the
  `Sample name` column.
- **Encoding**: UTF-8; a leading BOM (`utf-8-sig`) is tolerated.
- **Every input sample must appear** in the `Sample name` column. Submission is
  blocked otherwise.
- For **accession** input, `Sample name` must be the submitted accession
  (e.g. `SRR12345678`, `GCF_000005845.2`).
- When samples are matched, a trailing FASTA suffix
  (`.fasta`, `.fa`, `.fna`, optionally `.gz`) is stripped from both sides, so
  `ASM01` in metadata matches an `ASM01.fasta.gz` assembly.

### Example (tab-delimited)

```text
Sample name	Organism
24GNB-1676	Escherichia coli
24GNB-1737	Escherichia coli
24GNB-1738	Klebsiella oxytoca
24GNB-1739	Escherichia coli
24GNB-1740	Klebsiella pneumoniae
24GNB-1741	Klebsiella oxytoca
```

### Naming: the metadata prefix drives output names

The prefix is the part of the filename **before** `_samplesheet.txt`. For
`B07_samplesheet.txt` the prefix is `B07`, producing outputs such as
`B07_samplesheet_with_results.tsv` and `B07_results.xlsx`.

## Illumina FOFN — `samplesheet.fofn`

`runtype` is `paired-end`. Built by
[`scripts/2_create_fofn_bactopia.sh`](../scripts/2_create_fofn_bactopia.sh).

Rules the builder applies to each `*_R1` file in the input directory:

- **Sample name** = the basename up to the **first underscore**
  (`AGAR001_S1_L001_R1.fastq.gz` → sample `AGAR001`).
- Accepts `*_R1.fastq.gz` or `*_R1.fq.gz`; the matching `_R2` file must exist,
  or submission fails with `Missing R2`.
- `r1` = the R1 path, `r2` = the R2 path, `extra` is empty.
- Optional `INCLUDE_SAMPLE_REGEX` filters which sample prefixes are included.

Because the sample name is taken up to the first `_`, keep the meaningful
identifier before the first underscore. In an AGRF delivery the sample id
(`24GNB-1307`) is the part before the first `_`, and everything after it
(index, lane, read) is ignored when deriving the sample name:

```text
sample	runtype	r1	r2	extra
24GNB-1307	paired-end	/scratch/rg42/AGAR/raw_data/2025/B01/AGRF_CAGRF25090005_AAHHL2JM5/24GNB-1307_AAHHL2JM5_TAGCATAACC-GCTATGCGCA_L001_R1.fastq.gz	/scratch/rg42/AGAR/raw_data/2025/B01/AGRF_CAGRF25090005_AAHHL2JM5/24GNB-1307_AAHHL2JM5_TAGCATAACC-GCTATGCGCA_L001_R2.fastq.gz	
24GNB-1339	paired-end	/scratch/rg42/AGAR/raw_data/2025/B01/AGRF_CAGRF25090005_AAHHL2JM5/24GNB-1339_AAHHL2JM5_CCTCCGTCCA-CACATCGGTG_L001_R1.fastq.gz	/scratch/rg42/AGAR/raw_data/2025/B01/AGRF_CAGRF25090005_AAHHL2JM5/24GNB-1339_AAHHL2JM5_CCTCCGTCCA-CACATCGGTG_L001_R2.fastq.gz	
```

> Note: each row ends with a trailing tab — the empty `extra` field. Here
> `r1`/`r2` hold absolute paths and `extra` is empty; the sample id `24GNB-1307`
> is what must match the metadata `Sample name` column.

### Non-AGAR Illumina naming

- If the launcher creates the FOFN, the sample name comes from the FASTQ
  basename before the first underscore in `*_R1.fastq.gz`.
- If you supply your own `samplesheet.fofn`, its `sample` values are used as-is.
- Either way, metadata `Sample name` values must match the final FOFN samples.

## ONT FOFN — `samplesheet.ont.fofn`

`runtype` is `ont`. Built by
[`scripts/create_bactopia_input.sh`](../scripts/create_bactopia_input.sh) from
one compressed FASTQ per sample.

Rules:

- Accepts `*.fastq.gz` or `*.fq.gz` in the input directory (non-recursive).
- **Sample name** = filename with `.fastq.gz` / `.fq.gz` removed
  (`ONT01.fastq.gz` → sample `ONT01`).
- The ONT read path goes in `r1`; `r2` and `extra` stay empty.
- Duplicate derived sample names are rejected.

```text
sample	runtype	r1	r2	extra
ONT01	ont	/abs/path/ONT01.fastq.gz		
ONT02	ont	/abs/path/ONT02.fastq.gz		
```

Build one row by hand with `printf` (preserves the exact tabs):

```bash
printf 'sample\truntype\tr1\tr2\textra\nONT01\tont\t/abs/path/ONT01.fastq.gz\t\t\n' \
  > samplesheet.ont.fofn
```

### Metadata sheet for ONT

The metadata sheet is the same two-column `*_samplesheet.txt` as every other
input type (see [The Metadata Sheet](#the-metadata-sheet-required-for-all-input-types)).
The only ONT-specific requirement is that each `Sample name` equals the FASTQ
filename with `.fastq.gz` / `.fq.gz` removed:

```text
Sample name	Organism
ONT01	Escherichia coli
ONT02	Klebsiella pneumoniae
```

So `ONT01.fastq.gz` → sample `ONT01`, and `barcode07.fq.gz` → sample `barcode07`.
Every ONT sample must appear in the `Sample name` column.

> If one sample is split across multiple ONT FASTQs, concatenate its chunks
> into a single compressed FASTQ first — otherwise each file becomes a separate
> sample. Gzipped FASTQs concatenate safely with plain `cat`:
>
> ```bash
> cat ONT01_part1.fastq.gz ONT01_part2.fastq.gz > ONT01.fastq.gz
> ```
>
> The pipeline does **not** concatenate for you.

## Assembly FOFN — `samplesheet.assembly.fofn`

`runtype` is `assembly`. Built by
[`scripts/create_bactopia_input.sh`](../scripts/create_bactopia_input.sh).

Rules:

- Accepts `*.fasta.gz`, `*.fna.gz`, or `*.fa.gz` in the input directory.
- **Sample name** = filename with the FASTA extension removed
  (`ASM01.fasta.gz` → sample `ASM01`).
- The compressed FASTA path goes in `extra`; `r1` and `r2` stay empty.

```text
sample	runtype	r1	r2	extra
ASM01	assembly			/abs/path/ASM01.fasta.gz
ASM02	assembly			/abs/path/ASM02.fna.gz
```

> Bactopia treats these as finished assemblies — it does not run read QC, Flye,
> Racon, or Medaka on them.

## Accession List (no FOFN)

Accession input does **not** use a FOFN. Supply a plain, headerless text file
with one accession per line. SRA/ENA read accessions and NCBI assembly
accessions can be mixed.

```text
SRR12345678
ERX1234567
GCF_000005845.2
GCA_000006945.2
```

Rules:

- No header, no extra columns; one accession per line (whitespace in a line is
  rejected).
- Blank lines are ignored.
- Each accession must also appear in the metadata `Sample name` column.

The launcher splits the list into batches and passes each batch to Bactopia via
`--accessions`. Compute jobs need network access for the downloads.

## Validating Before You Submit

Two checks are worth running before a real submission.

**1. Metadata covers every input sample** —
[`scripts/validate_metadata_samples.py`](../scripts/validate_metadata_samples.py):

```bash
python3 scripts/validate_metadata_samples.py \
  --input   /path/to/samplesheet.ont.fofn \
  --input-type ont \
  --metadata /path/to/B07_samplesheet.txt
```

For accession input, pass the accession list as `--input` with
`--input-type accession`. The check fails if any input sample is missing from
the metadata `Sample name` column.

**2. FOFN structure** — [`scripts/validate_bactopia_fofn.sh`](../scripts/validate_bactopia_fofn.sh)
checks the manifest is well formed.

**3. Full dry run** — the launcher's own `--dry-run` validates config,
metadata, FOFN handling, and key dependencies without submitting jobs:

```bash
./bin/bactopia-workbench submit gadi --dry-run \
  INPUT_SOURCE METADATA_DIR RESULTS_ROOT 50
```

## Common Pitfalls

- **Stale FOFN reuse**: if `samplesheet.fofn` already exists in `METADATA_DIR`,
  the launcher reuses it. After changing the raw FASTQ folder, delete or move
  the old FOFN so the batch list is rebuilt.
- **Wrong first underscore for Illumina**: sample = text before the first `_`.
  A name like `Site_01_R1.fastq.gz` becomes sample `Site`, not `Site_01`.
- **Sample name mismatch**: FOFN sample names must exactly match metadata
  `Sample name` values (after FASTA-suffix stripping). This is the most common
  cause of dropped or unmapped samples.
- **Lost tabs**: FOFN files are strictly tab-delimited. Editing in a tool that
  converts tabs to spaces will break parsing — prefer `printf` or a
  tab-preserving editor.
